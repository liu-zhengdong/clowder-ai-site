技能与能力进化

核对于 2026-10-19 4b5dc96b5上一层 · Clowder AI：新人导览packages/api/src/skills/packages/api/src/domains/capabilities/cat-cafe-skills/packages/mcp-server/src/
30 秒版

Clowder 不把所有指令塞进一个系统提示词，而是把「会做某件事」打包成按需加载的技能；同时它给自己留了一条受治理的通道，让能力本身可以一层层改进而不是靠人反复改提示词。这一块管「会什么」和「怎么变强」。

边界

负责：技能的定义、路由与加载时机、技能消耗的可追溯回执、能力画像与提示；以及「能力进化」这条受治理的改进通道（提出 → 准备 → 试改 → 保留/调参/回滚/退役）。

不负责：技能里写的内容本身好不好（那是内容质量问题，走 协作纪律与治理 的评审与 eval）；工具怎么暴露给非 Claude 模型（那是 插件与外部连接 与 MCP 面治理）。

怎么运转

这条链的设计意图是让改进有出处。技能不是凭空改的：先是同一种摩擦反复出现，再进入受治理的通道，改完要能回滚。这样「系统变强」这件事本身是可审计的，而不是某次灵机一动。

坑

把技能当成「另一套提示词」随便追加 → 路由表与技能库脱节，技能写得再好也不触发，或者到处都触发 → 新增技能时三件事一起做：建 SKILL.md、在路由表加条目、跑技能一致性检查。

以为装了技能就等于会用 → 服务端与本地是两条装配路径，本地生效不代表服务端生效 → 改技能后两边都验一次。

改了技能却没有回执 → 无法判断这次改动是改善还是恶化，只能凭印象 → 技能使用与产出的回执要能查，才谈得上「进化」。
