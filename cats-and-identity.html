猫与身份

核对于 2026-10-19 4b5dc96b5上一层 · Clowder AI：新人导览cat-template.jsonpackages/api/src/config/cat-catalog-store.tspackages/api/src/domains/cats/services/session/packages/shared/src/types/cat.tspackages/api/src/domains/packs/
30 秒版

Clowder 里的「猫」不是一次对话，而是一个有名字、有品种、有性格、有模型的长期成员。这一块管三件事：成员是谁（花名册与人格）、它此刻跑在哪个运行时会话里、以及它背后接的是哪家 CLI / 哪个模型。

边界

负责：成员目录与人格配置、花名册与能力画像、每只猫的运行时身份与会话绑定、跨会话与上下文压缩后的身份连续性、以及 agent CLI 提供商（Claude Code / Codex / Gemini / Antigee / opencode / Kimi 等）的接入与调用。

不负责：它记得什么（交给 记忆与证据）；它刚说了什么（交给 对话与投递内核）；页面上的「看得见的猫」怎么画（交给 在场·生活与作品）。

业务场景

你想加第二只猫。你在设置里选一个品种，填名字和性格，选一个模型账户——几分钟后 Hub 的花名册里多了一只猫，你在任意 thread 里 @ 它就能说话。这三步背后是三个不同的系统：品种与人格是配置，账户与凭据是身份，能说话是运行时。新人最常把它们混成一个「猫对象」，于是改一处以为全都改了。

怎么运转

关键点：身份先于一切。一次调用进来时，系统先确定「这是哪只猫、替谁干活」，再决定给它看什么上下文、允许它做什么、把回执算在谁头上。把这一步做错，后面所有审计、追溯和权限判断都会跟着错，而且错得很安静。

坑

用 GitHub 登录名判断「是不是同一只猫」 → 一家里所有猫共用同一个账号，跨个体 review 会被误判成自审，或者自审被当成交叉审 → 跨个体判据是猫的身份，不是登录账号；两个人格不同的猫就算同一个账号也是跨个体。

以为「换了模型账户」等于「换了猫」 → 人格、历史、记忆和别人的印象全部错位 → 账户是猫的一个属性，换账户改属性，不要新建一只猫。

把 provider 的特有行为写进核心 → 每接一家新 CLI 就要改核心路由和类型联合，越接越慢（这是 F241 立项的直接原因） → 新增提供商做成插件/运行时接入，核心只认契约。

上下文压缩之后假设猫还记得 → 它不记得，而且不会告诉你它不记得 → 需要跨压缩存活的东西必须走持久层（见 记忆与证据），不能靠「刚才说过」。

待确认：packs 目前是 packages/api/src/domains/packs/ 下的一个域，不是独立包；它和插件框架的边界（谁能声明资源、谁能被授权）需要仓库主人确认后再细写。
